SM-146

Check off

Decide push vs pull for content delivery

USB push and Wi-Fi pull solve different rooms. The board treats them as one argument, so neither has a finish line.

Where it stands

V1 delivery is USB. The Agent polls the cloud and writes 1024-byte chunks to the panel. Each chunk has a CRC-32. The panel answers ACK or NAK. The full frame is 48,000 bytes, which is 800 by 480 at 1 bit. That protocol is firmware/usb_protocol.py and firmware/fennsill/fennsill.ino.

Done when

The card says: V1 is USB push via the Agent. Wi-Fi pull is FN-034 plus SM-052, after the pilot.

FN-032

Check off

Chunked transfer with per-chunk ACK and checksum

A full frame has to survive a noisy cable. The card is the reliability of the USB push.

Where it stands

The host sends magic AFC1, then 1024-byte chunks, each with a CRC-32. The panel answers ACK with the chunk index, or NAK. A show packet, magic AFS1, carries the CRC of the whole 48,000-byte frame. This is firmware/usb_protocol.py and the matching reader in the sketch.

Done when

The design card is checked. FN-157 includes one bad-chunk proof: a corrupted chunk is NAKed, the retry lands, and the panel shows the frame.

Work

  1. Check FN-032 as the protocol you ship.
  2. Put the bad-chunk retry on the FN-157 checklist.
  3. Leave frame size alone until FN-024 says 2-bit is worth a larger buffer.

Wi-Fi image download is a different transport. It does not replace this USB format for V1.

FN-035

Check off

Over-the-air firmware updates

You need a way to fix a panel that already left the bench, without asking the owner to run Factory.

Where it stands

If Wi-Fi is saved, boot can fetch an HTTPS manifest. The signature is an HMAC over version and sha256. The binary URL has to be https, and the download hash has to match. The panel shows an update prompt. The top button installs. The middle button skips. Serial errors are ERR bad signature and the ota url, http, begin, write, sha, and end failures. Buyers are not given a tool that publishes manifests.

Done when

The mechanism card is checked. The operator note on the OPS card says how you publish a manifest, and that the panel needs saved Wi-Fi for OTA to run.

Work

  1. Check FN-035 as the updater you have.
  2. Write the publish steps into the operator note: sign version plus sha256, host the binary on https, point the manifest URL, confirm the panel shows the prompt.
  3. Keep OTA off the V1 buyer Quick Start until a pilot panel has actually installed one signed build. USB reflash from Factory remains the recovery path.

A buyer-facing channel that publishes firmware would undo the operator-only rule in the cloud brief.

Where it stands

Done when

When the display never releases BUSY, Desk and Factory show display not detected, and the USB port is usable again for a later push.

Work

  2. Surface that line in Factory's log. Factory is who flashes and who will see a dead panel first.
  3. Surface the same line in Desk when a push fails for that reason, next to the existing cloud and USB status.
  4. Add the case to FN-157: ribbon unplugged or panel absent, expect the sentence within about 15 seconds, then a later good push still works.

The timeout itself is in the sketch. This card is the person seeing it.
